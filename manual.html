01 / START HERE

先選擇，
再開始建立。

BEC 的品牌與藝人頁面使用同一套核心程式，但分類方式不同。第一步先決定這張頁面適合哪一種模式。

01 / BRAND

品牌專頁

單層分類。適合 rhode、alo 及一般選物品牌。分類清楚、頁面簡潔，適用於商品類型相對集中的品牌。

02 / ARTIST

藝人專頁

兩層分類。先選「依專輯／系列」或「依商品類型」兩大入口；接著挑選專輯或商品大類，最後才顯示黑膠、CD、上衣等細項。適合 Taylor Swift、BTS。

已完成的 rhode 是品牌模式的穩定範例，保留七個分類：全部商品、護膚保養、唇部、眼部、臉頰、美妝工具、服飾 CLOTHING。沒有必要為了更新手冊而重新改動它。
02 / THE WORKFLOW

一張頁面，
六個步驟。

以下流程適用於未來的每一位管理者。只要依順序操作，就不需要接觸共用 CSS 或 JavaScript 原始碼。

01

在 1shop 建立獨立網頁

進入「網頁」新增頁面，先設定品牌／藝人名稱、Banner 和商品展示。測試期間先不要加入正式主選單。

02

開啟 BEC Collection Builder

選擇 BRAND 或 ARTIST；輸入完整名稱與英文識別碼，例如 Taylor Swift 使用 taylor-swift。上線後盡量不要改識別碼，以免既有分類連結失效。

03

選擇商品分類

品牌模式先選產業範本（美妝、服飾、水瓶、家居、3C、生活等），再勾選商品類型，也可跨產業混搭或視覺化新增分類，不需要手打三欄文字。藝人模式先選主分類，再勾選子分類。自訂項目按「＋ 新增子分類」，直接選主分類並填寫名稱、英文代碼；原生標題會自動帶入，完全不必輸入分隔符號。

04

產生並貼上代碼

按「產生 1shop 程式」，複製完整內容，貼到這張網頁唯一一個 Collection「程式」區塊。不要和舊版 Sticky Nav 並存。

05

加入原生標題與商品

「全部商品」若缺失，v1.2 可協助生成標題與錨點。其他分類需在對應商品展示前建立 1shop 原生「文字」標題，文字與產生器設定一致。系統不會替你建立商品展示。

06

驗收後正式發布

測試桌面和手機、錨點、吸頂、Mega Menu、圖片、價格及 SEO，確認正常後再加入品牌／藝人主選單。

商品分類，
該放在哪裡？

03A / SERIES MANAGEMENT

一張專輯，
所有周邊。

已經在 1shop 建立好十幾張專輯的管理者，請先使用 舊版藝人導覽一鍵升級工具，直接匯入目前網頁的完整「程式」區塊並轉換，不必重建任何專輯與分類。

藝人頁新增「作品／專輯系列」管理。前台固定先顯示「依專輯／系列」與「依商品類型」兩個入口，不會把專輯名稱與商品分類全部鋪在同一排。導覽的所有層級均採平均寬度排列，手機版為雙欄等寬配置。大型藝人使用精簡雙入口＋可收合分類抽屜：初始只顯示「依專輯／系列」和「依商品類型」，選擇後才顯示專輯及商品細項。選擇細項、點選單外、按 Esc 或開始捲動後收合；手機版保持雙欄並限制選單最大高度。每張專輯、巡演或期間限定企劃只需新增一次，再勾選它販售的商品類型，便能產生專屬的系列分類與錨點。藝人模式自訂的子分類也會自動同步到每個既有與新建立的系列，不需要重複輸入。

01

建立系列

在 Collection Builder 選 ARTIST，向下找到「作品／專輯系列」，點「＋ 新增系列」。輸入完整正式名稱、英文代碼及系列類型。

02

勾選系列商品類型

例如 The Life of a Showgirl 勾選黑膠、CD、上衣與杯具。可按「複製設定」快速建立下一個系列，不必重新勾選全部。

03

產生並配置商品

產生器會建立「系列 · 名稱」主分類和商品類型子分類。請在 1shop 對應商品展示上方加入原生文字標題，文字需對應產生器產生的「系列名稱 ／ 商品類型」。同一商品可以從作品系列和商品類型兩個方向被展示，但不需要建立兩個商品紀錄。

目前是第一階段：產生分類導覽與錨點配置，尚未自動抓取 1shop 商品並建立交叉篩選。系列群組會顯示在藝人頁的主分類列；系列多時需檢查手機版橫向導覽。已成功的 rhode 品牌模式不受影響。

05 / KEEP IT UPDATED

維護很簡單，
但要分清楚。

PAGE CONTENT

只改這個品牌

調整這一頁的分類：品牌模式使用產業範本與勾選清單；在 Builder 重新產生完整設定，替換原本唯一的「程式」區塊，再同步更新 1shop 標題與商品展示。無須碰共用核心。

SHARED SYSTEM

修改全部頁面

吸頂、動畫及外觀等共用功能由 GitHub 程式庫管理。先用測試頁驗證，再安排更新與快取版本；共用檔案改動可能影響所有引用頁面。

目前參考版本：共用 CSS v1.1、共用 JavaScript v1.2；藝人新版三階層導覽使用 Artist CSS／JS v2.0。不要為了更新手冊而修改已成功的 rhode 共用設定。
06 / QUICK HELP

遇到問題，
先看這裡。

點擊子分類沒有反應

檢查 Builder「對應原生標題」是否和 1shop 的原生文字方塊相符；該標題必須放在商品展示之前。不要把商品卡片當作標題。

「全部商品」的標題或錨點消失

確認最前面是「全部商品」連結、導覽放在全部商品展示之前，並載入 bec-collection.js?v=1.2。避免同頁放兩份共用導覽。

導覽閃爍或出現兩條

檢查是否同時保留舊版 Sticky Nav v4 與新版共用模板，或重複貼入兩份 Collection 設定。請先備份，再移除重複導覽；不要刪掉原生商品標題。

藝人主分類不能切換

確認產生器選的是 ARTIST，且完整代碼包含 bec-artist.css、bec-artist.js 與 nav 的 bec-artist 類別。

全站 Mega Menu 被導覽蓋住

確認共用 CSS／JavaScript 正常載入，再測試滑鼠移入與移出 Header 品牌選單；不要任意增加浮動列的 z-index。

更新後還是舊版本，或出現 404

檢查 GitHub Pages 是否從 main /(root) 發布、檔案 URL 是否能打開，並確認網址的 ?v= 版本參數。不要直接刪除已上線的商品頁。

商品圖片出現 .avif 404

這是獨立於 Collection 導覽的圖片 Hover 問題。需要在 Safari Network 核對來源，勿直接修改共用導覽以處理。

08 / VERSION CONTROL

更新版本，
不重建專案。

Collection Builder 會在本機自動保存正在編輯的分類與專輯設定。編輯完成後，按「儲存目前專案到升級中心」，下次只需載入專案並按自動升級，就能直接複製最新版完整 HTML。

01

保留目前專案

在 Builder 按「儲存目前專案到升級中心」。新專案可以直接建立；既有 1shop 頁面請先貼入該頁「程式」區塊原碼。避免重新逐張輸入專輯。

02

讀取正式版本並升級

開啟 自動升級中心，載入已儲存的品牌／藝人專案，按「自動升級到正式版」。系統從 versions.json 讀取正式資產版本並比對原始分類、標題、錨點與群組。

03

完整替換與驗收

比對專輯與分類數量後，複製完整代碼，貼回 1shop 原本的單一程式區塊。確認頁面吸頂、錨點、Mega Menu、手機版及商品展示皆正常。升級工具不會自動修改 1shop。

資料保存在 Safari 本機。請定期在 Builder 下載設定 JSON，並在升級中心匯出全部專案 JSON；切換電腦或清除瀏覽器資料前務必備份。共用版本的重大架構變動仍需要專門的相容性遷移，不能保證任何未來版本都可以直接升級。
